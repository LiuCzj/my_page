# 它是什么

首页那颗可以点的角色，点开是一个问答面板。访客问「你有哪些作品」，它按 token 逐字把答案打出来，看起来像在跟本人聊天。

整个链路只有三段，没有引入任何 AI SDK：

1. 浏览器 `POST /api/assistant`，带上对话历史和当前语言
2. Route Handler 把请求转发给模型接口，`stream: true`
3. 模型的 SSE 流原样回传，浏览器逐块解析、逐字追加到气泡里

# 密钥为什么必须留在服务端

`app/api/assistant/route.ts` 是服务端代码，环境变量在这里读：

```ts
const apiKey = process.env.ASSISTANT_API_KEY;
```

只要不写成 `NEXT_PUBLIC_` 前缀，Next 就不会把它打进浏览器包。这是唯一需要记住的规则——前缀是公开的开关，加错了等于把密钥贴在页面上。

同一个文件里还要显式声明运行环境：

```ts
export const runtime = 'nodejs';
```

因为默认可能被分配到 Edge Runtime，而 Edge 上读不到某些 Node API，且请求超时行为不一样。

# SSE 解析：分块边界不对齐

这是整个实现里唯一真正的坑。

服务端推送的是 `text/event-stream`，每行形如 `data: {...}`。直觉写法是拿到一个网络分块就 `JSON.parse`，但**网络分块的边界和 SSE 的行边界没有任何关系**：

- 一个分块可能只到 `data: {"cho` 就断了
- 也可能一次给两三行

正确做法是维护一个缓冲区：累积 → 按换行切 → 只消费完整行 → 把最后那段不完整的留到下一轮。

```ts
let buffer = '';
for (;;) {
  const { done, value } = await reader.read();
  if (done) break;
  buffer += decoder.decode(value, { stream: true });

  const lines = buffer.split('\n');
  buffer = lines.pop() ?? '';   // 最后一段可能不完整，留到下一个分块

  for (const line of lines) {
    // 只处理完整行
  }
}
```

`lines.pop()` 那一行是关键。少了它，偶尔会有一个 JSON 解析失败，表现为「答案中间少几个字」——很难复现，也很难查。

# 几个刻意的设计

- **欢迎语不存进消息列表**，每次从配置现取。这样切到英文它立刻跟着变，不会出现「历史记录里躺着中文、界面已经是英文」的割裂。
- **历史存 localStorage**，上限 20 条。刷新、跳走再回来，对话还在。
- **失败的气泡带重试**，重发前先把这条错误气泡删掉，避免把同一个问题重复塞进上下文多花一份 token。
- **模型输出会被清洗一遍**。提示词里禁了 Markdown，但实测仍然会吐 `**加粗**`，所以前端做了确定性的清理，而不是继续往提示词里堆话。

# 站内指路

分身的系统提示词里写死了本站有哪些页面，因为不写它就会编：

> 本站有三个页面：首页、项目页 `/projects`、笔记页 `/notes`。要指路就指这几处；不要提不存在的路径。

这段提示词有个副作用：**加了新页面必须同步更新它**。忘了改，分身会一本正经地告诉访客「本站只有一页」，而页面上明明挂着新链接。

# 没做的事

- 没有接入任何 AI SDK。转发 + 解析 SSE 一共几十行，为它引一个依赖不划算。
- 没有做多轮工具调用。当前只回答问题，不查数据、不执行动作。
- 没有做用户侧限流。速率限制在模型服务商那一侧，本站只做了输入长度上限（2000 字）来挡住最明显的一类滥用。
